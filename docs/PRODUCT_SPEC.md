# 삼삼오오 웹게임 기획 및 구현 인계

## 1. 제품 목적

친구나 가족이 삼삼오오 모였을 때, 하나의 화면을 함께 보며 사진 속 인물이나 사물의 이름을 맞히는 웹 파티 게임을 만든다. 예능의 사진 퀴즈처럼 설명 없이 바로 시작할 수 있고, 화면에서 멀리 떨어져 있어도 사진과 남은 시간이 잘 보여야 한다.

서비스 가칭은 **삼삼오오**다. 예능 프로그램의 공식 서비스로 보이게 하는 로고나 방송 화면은 사용하지 않는다.

구현 결과는 정적 웹앱으로 배포했다. 아래 항목은 첫 버전의 기준 및 후속 개선 범위로 유지한다.

## 2. 요구사항과 기본 가정

### 사용자 필수 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 게임 종류 | 인물 버전, 사물 버전, 인물·사물 혼합 버전 |
| 출제 | 사진을 무작위 순서로 표시 |
| 재출제 | 한 번 나온 문제는 뒤로 보내 바로 반복되지 않게 처리 |
| 제한 시간 | 문제마다 5초 카운트 |
| 화면 | 여러 사람이 함께 볼 수 있도록 크게 표시 |
| 최종 이용 방식 | 웹 주소로 접속해서 플레이 |

### 구현을 위한 권장 기본값

아래는 사용자가 별도로 확정한 조건이 아니라, 바로 구현할 수 있도록 정한 기본값이다.

- 참가자들은 정답을 말로 외친다. 한 명의 진행자가 화면을 조작하고 정답 여부를 판단한다.
- 여러 휴대폰을 연결하지 않고 한 기기에서 진행한다. 로그인도 필요 없다.
- 먼저 인물·사물·인물과 사물 혼합 버전 중 하나를 선택한다. 인물 버전에서는 전체·국내·해외·만화 및 동화 캐릭터 항목을 추가로 고를 수 있다.
- 제한 시간은 5초로 고정한다. 정답 공개 후 다음 문제는 진행자가 넘긴다.
- 라운드당 10문제를 진행한다. 라운드 종료 후 같은 카테고리로 계속할 수 있다.
- 운영 콘텐츠 목표는 인물 200개·사물 200개 이상이다. 홈에는 문제 수를 표시하지 않는다.

## 3. 사용 흐름

1. 웹 주소에 접속한다.
2. 홈에서 인물·사물·혼합 버전 중 하나를 선택한다. 인물 버전은 세부 항목을 선택할 수 있다.
3. `시작하기`를 누른다. 첫 사진 로딩이 끝나면 사진과 5초 타이머를 함께 보여준다.
4. 참가자들이 이름을 외친다. 맞혔다면 진행자가 `정답!`을 누르고, 모르겠다면 `패스`를 누른다.
5. 정답 처리·패스·시간 초과 중 하나가 발생하면 타이머를 멈추고 정답을 공개한다.
6. 진행자가 `다음 문제`를 눌러 계속한다.
7. 10문제가 끝나면 정답 수를 보여준다. `한 판 더`는 기존 출제 순서를 이어서 진행한다.

## 4. 화면 설계

### 홈

- 제목: `삼삼오오`
- 한 줄 설명: `사진을 보고 5초 안에 이름을 외쳐보세요!`
- 버전 카드 3개: `인물 버전`, `사물 버전`, `인물·사물 섞기`
- 인물 항목 선택: `전체 인물`, `국내 인물`, `해외 인물`, `만화·동화 캐릭터`
- 규칙: `한 판 10문제 · 문제당 5초`
- 주 동작: `시작하기`
- 보조 동작: `전체화면`, `소리 켜기/끄기`
- 키보드 안내는 짧게 보여주고 터치만으로도 모든 기능을 사용할 수 있게 한다.

### 게임 진행

```text
┌─────────────────────────────────────────────────────┐
│ 인물 이름 맞히기         3 / 10       정답 2   나가기 │
│                                                     │
│                       [ 5 ]                         │
│                                                     │
│              ┌──────────────────────┐               │
│              │                      │               │
│              │       문제 사진      │               │
│              │                      │               │
│              └──────────────────────┘               │
│                                                     │
│             [정답!]     [패스]     [일시정지]        │
└─────────────────────────────────────────────────────┘
```

- 사진이 화면의 주인공이다. PC에서는 사용 가능한 게임 영역의 약 65~75%를 사진 영역에 배정한다.
- 사진의 얼굴이나 사물이 잘리지 않도록 기본 표시 방식은 `object-fit: contain`으로 한다.
- 제한 시간은 사진 위쪽 별도 영역에 크게 표시해 얼굴을 가리지 않는다.
- 진행 중에는 정답 텍스트를 표시하지 않는다. 접근성 이름에도 정답을 넣지 않고 `인물 문제 사진` 등의 설명을 사용한다.
- 남은 시간이 2초 이하면 숫자와 진행 막대로 긴박함을 알린다. 색상에만 의존하지 않는다.
- 정답 공개 시 사진을 유지하고 그 아래 큰 글씨로 이름을 보여준다.
- 마지막 문제의 정답 공개 화면에는 `다음 문제` 대신 `결과 보기`를 표시한다.

### 정답 공개 상태

- 상태 문구: `정답!`, `패스`, `시간 초과!` 중 하나.
- 정답 이름과 필요한 경우 인정 가능한 다른 이름을 보여준다.
- 패스·시간 초과 직후 늦게 맞힌 답을 인정할 수 있도록 `정답으로 인정`을 제공한다.
- 이미 정답으로 인정된 문제는 추가 점수를 주지 않는다.
- 다음 문제로 넘어가면 이전 결과를 수정하지 않는다.

### 결과

- `10문제 중 7문제 정답!`
- `정답 7 · 패스 1 · 시간 초과 2`처럼 최종 판정별 개수를 표시한다.
- `정답으로 인정`한 문제는 원래 패스·시간 초과 집계에서 빼고 정답으로 옮긴다.
- `한 판 더`: 점수와 라운드 문제 번호를 초기화하고, 남은 출제 대기열에서 이어서 진행한다.
- `카테고리 선택`: 홈으로 돌아간다. 카테고리별 대기열은 유지한다.
- `출제 기록 초기화`: 확인 후 현재 카테고리 대기열을 새로 섞는다.

## 5. 무작위 출제와 중복 방지

매번 전체 목록에서 무작위로 하나씩 뽑는 방식은 바로 전에 본 사진이 다시 나올 수 있으므로 사용하지 않는다. **한 번 섞은 대기열을 끝까지 소비한 다음 다시 섞는다.**

### 출제 규칙

1. 카테고리별 사용 가능한 문제 ID를 모아 Fisher–Yates 방식으로 섞는다.
2. 대기열 맨 앞의 문제를 꺼내고, 사진을 정상 표시한 시점에 해당 문제를 `본 문제` 목록으로 보낸다.
3. 한 번 본 문제는 미출제 문제를 모두 보여주기 전까지 다시 출제하지 않는다. 이것이 “한 번 뜬 문제는 나중으로 보내기”의 의미다.
4. 미출제 문제가 소진되면 본 문제 목록을 다시 섞어 새 대기열로 사용한다.
5. 문제가 2개 이상이면 새 대기열 첫 문제는 직전 문제와 다르게 조정한다.
6. 카테고리별 대기열과 직전 문제 ID를 브라우저에 저장한다. 라운드 종료·홈 이동·새로고침 이후에도 유지한다.
7. `출제 기록 초기화`만 현재 카테고리의 순서를 처음부터 새로 만든다.

### 예시

문제 A, B, C, D가 있을 때 첫 순서가 `C → A → D → B`라면, 네 문제를 모두 보여주기 전까지 C는 다시 나오지 않는다. 다음 순서는 다시 무작위로 정하되 B로 시작하지 않는다.

### 예외

- 사진을 보여준 뒤 홈으로 나가거나 새로고침해도 이미 본 문제로 취급한다.
- 새로고침하면 홈으로 돌아가며 진행 중 점수는 초기화된다. 출제 기록은 유지한다.
- 사진 로딩 실패는 본 문제·점수·문제 번호에 포함하지 않는다. 현재 페이지 세션에서 해당 문제를 제외하고 다음 문제를 찾는다.
- 사용 가능한 문제가 10개 미만이면 라운드 길이를 해당 개수로 줄인다. 예: 6개라면 `총 6문제로 진행합니다`를 알린다.
- 문제가 1개면 1문제 라운드로 진행하고, 같은 문제의 반복 가능성을 알린다.
- 문제가 0개면 시작을 막고 `아직 준비된 문제가 없어요`를 보여준다.
- 라운드 도중 실패한 이미지는 무한 재시도하지 않는다. 모든 후보를 시도해도 표시할 문제가 없으면 진행한 문제 수로 결과를 보여주고 콘텐츠 오류를 안내한다.
- 라운드 중 대기열 주기가 바뀌어도 같은 라운드에서 이미 표시한 ID는 건너뛴다. 건너뛴 ID는 삭제하지 않고 대기열에 남긴다.
- 콘텐츠 목록이 변경되면 없어진 ID를 제거하고, 새 ID를 아직 보지 않은 대기열에 추가한다.
- 브라우저 저장소가 차단되었거나 저장값이 손상되면 메모리에서 새 대기열로 진행한다. 게임 자체를 막지 않는다.

## 6. 5초 타이머와 판정

### 타이머

- 사진 다운로드 및 디코딩이 끝나고 화면에 표시되는 시점부터 5,000ms를 센다.
- 숫자는 `5 → 4 → 3 → 2 → 1 → 시간 초과` 순서로 표시한다.
- 타이머가 끝난 후 `0`에서 추가로 1초를 기다리지 않는다.
- 남은 시간은 단순 반복 횟수가 아니라 기준 종료 시각과 현재 시각의 차이로 계산한다.
- 제한 시간 내 `정답!` 또는 `패스`를 누르면 즉시 타이머를 종료한다.
- 사진 로딩 중에는 타이머가 흐르지 않는다. 다음 후보 사진은 미리 불러올 수 있지만, 미리 불러오는 것만으로 본 문제로 처리하지 않는다.
- `일시정지`하면 남은 시간을 보존하고 사진을 가린다. `계속하기`를 누르면 남은 시간부터 재개한다.
- 탭 전환·앱 전환으로 페이지가 숨겨지면 자동 일시정지한다. 복귀 후에는 사용자가 `계속하기`를 누른다.

### 상태와 입력

`홈 → 로딩 → 문제 표시 ↔ 일시정지 → 정답 공개 → 다음 문제 로딩 / 결과`

- 로딩·일시정지 중에는 정답·패스·다음 문제 입력을 받지 않는다.
- 정답 공개 뒤 자동으로 다음 문제로 넘어가지 않는다. 참가자에게 정답을 확인할 시간을 준다.
- 타이머 종료와 정답 클릭이 겹치면 한 번만 판정한다. 이벤트 처리 시점에 이미 마감 시각이 지났다면 시간 초과로 처리하며, 이후 `정답으로 인정`은 가능하다.
- 빠른 연속 클릭이나 키 반복 입력으로 문제 두 개를 건너뛰지 않도록 상태별로 동작을 제한하고 전환 중 버튼을 잠근다.

| 상태 | 입력 | 동작 |
| --- | --- | --- |
| 문제 표시 | `Enter` | 정답 처리 및 공개 |
| 문제 표시 | `Space` | 패스 및 공개 |
| 정답 공개 | `Space` | 다음 문제 또는 결과 보기 |
| 문제 표시 / 일시정지 | `P` | 일시정지 / 계속하기 |
| 공통 | 화면의 전체화면 버튼 | 브라우저 지원 범위에서 전체화면 전환 |

키를 누르고 있는 동안 발생하는 반복 이벤트는 무시한다. 입력창이나 버튼에 포커스가 있을 때 기본 키 동작과 전역 단축키가 이중 실행되지 않도록 한다.

## 7. 시각 디자인과 기기 대응

- 어두운 배경, 선명한 포인트 색상, 굵고 읽기 쉬운 한글 글꼴을 기본 방향으로 한다.
- 기본 데스크톱 기준 타이머 숫자는 약 80~120px, 정답은 약 40~64px로 시작하고 화면 크기에 따라 조정한다.
- 버튼 터치 영역은 최소 48px 높이로 잡고 동작 사이 간격을 확보한다.
- PC·태블릿 가로 화면을 주요 이용 환경으로 잡되 휴대폰 세로 화면도 지원한다.
- 휴대폰 세로 화면에서는 가로 이용을 권장할 수 있지만 강제 회전은 하지 않는다.
- 전체화면을 지원하지 않는 환경에서도 화면 내부 게임 모드는 정상 작동해야 한다.
- 전체화면 요청은 사용자 클릭에서 실행하고, 거절·종료되어도 게임 상태를 유지한다.
- 사진·타이머·정답·하단 버튼이 작은 화면에서도 동시에 보이도록 한다. 모바일 주소창과 안전 영역을 고려한다.
- 소리는 기본 꺼짐이다. 켜면 마지막 3초의 짧은 효과음과 종료음을 제공하며, 소리 없이도 규칙을 파악할 수 있어야 한다.
- 과한 깜빡임과 화면 흔들림은 피하고, 모션 감소 설정을 존중한다.
- 정답 공개와 타임아웃은 보조 기술에 알리되 남은 시간을 매 프레임 읽게 하지 않는다.

## 8. 문제 콘텐츠

### 사진 선정

| 카테고리 | 선정 기준 |
| --- | --- |
| 인물 | 한 사람 또는 한 캐릭터가 선명한 사진·삽화, 이름 표기나 정답을 알려주는 자막 없음 |
| 사물 | 대표 사물이 명확한 사진, 정답을 알려주는 문구나 여러 사물 간 혼동이 적음 |

- 인물은 연예인·스포츠 스타·역사 인물·만화 및 동화 캐릭터를 고르게 포함한다. 사물은 생활용품·주방용품·문구·도구·탈것·악기를 섞는다.
- 정답은 진행자가 판단하며, 사물의 동의어와 흔한 명칭 차이를 데이터에 기록한다.
- 예: `헤어드라이어`의 인정 답안은 `드라이기`, `드라이어`를 포함할 수 있다.
- 첫 버전은 난이도 설정 없이 널리 알려진 인물과 알아보기 쉬운 사물로 시작한다.
- 공개 배포에 사용할 수 있는 자체 제작·허가·라이선스 확인 사진을 사용하고 출처와 이용 조건을 기록한다.
- 검색 결과 사진이나 방송 캡처를 무조건 수집해 쓰지 않는다. 외부 이미지 URL에만 의존하는 핫링크도 피한다.
- 실제 사진 확보가 되지 않은 인물 문제를 이모지나 이름 카드로 대체해 완성으로 보고하지 않는다.

### 데이터 예시

아래 경로는 스키마 설명용이며 실제 파일이 아니다. 구현 모델은 실제 이미지와 메타데이터를 채워야 한다.

```json
{
  "id": "object-001",
  "category": "object",
  "answer": "헤어드라이어",
  "acceptedAnswers": ["드라이기", "드라이어"],
  "imagePath": "/images/objects/hair-dryer.webp",
  "sourceUrl": "",
  "creator": "",
  "license": "",
  "attribution": "",
  "enabled": true
}
```

저장 데이터의 `celebrity`, `history`, `character`, `person`은 화면에서 모두 `person` 문제군으로 합치고, `object`는 사물 문제군으로 사용한다. ID는 전체 데이터에서 고유해야 한다. 출처·제작자·라이선스는 실제 확보 방식에 맞춰 채우고, 필요한 크레딧은 별도 출처 화면에서 볼 수 있게 한다.

## 9. 첫 버전 범위와 구현 방향

### 포함

- 카테고리 선택, 사진 표시, 대기열 출제, 5초 타이머.
- 정답·패스·시간 초과 처리, 정답 공개, 라운드 결과.
- 일시정지, 전체화면, 키보드·터치 조작, 소리 토글.
- 반응형 화면, 이미지 로딩 실패 처리, 출제 기록 저장·초기화.
- 실제 문제 데이터, 사진 출처 화면, 공개 웹 배포.

### 후속 확장

팀전, 난이도 선택, 제한 시간 변경, 문제 수 선택, 사용자 사진 업로드, 음성 정답 인식, 여러 기기 동시 접속, 계정·랭킹은 첫 버전에서 제외한다.

### 권장 기술 구성

- 별도 백엔드 없이 정적 웹앱으로 시작한다.
- 프런트엔드 기본 제안은 React + TypeScript + Vite다. 다른 구성이 더 적합하면 요구사항을 유지한 채 변경 가능하다.
- 문제 데이터는 정적 JSON 또는 TypeScript 파일로, 사진은 배포 자산으로 관리한다.
- 브라우저 저장소에는 카테고리별 미출제·본 문제 목록, 직전 문제, 콘텐츠 버전, 소리 설정을 저장한다.
- 게임 상태와 타이머 제어를 화면 컴포넌트에서 분리해 판정 중복을 방지한다.
- 이미지 크기와 파일 용량을 최적화하고, 현재 문제와 다음 후보 위주로 로딩한다.
- 클라이언트에 정답 데이터가 들어가는 친목 게임이다. 경쟁 서비스 수준의 정답 은닉은 범위에 포함하지 않는다.

## 10. 배포와 인계 결과물

후속 모델은 다음 결과물을 남긴다.

1. 로컬에서 실행 가능한 프로젝트와 실행·빌드 명령.
2. 인물·사물 문제군의 실제 문제 데이터, 사진 파일, 출처 및 이용 조건.
3. HTTPS로 접속 가능한 공개 URL. 특정 호스팅 공급자는 고정하지 않는다.
4. 모바일과 PC에서 확인한 결과 및 핵심 로직 테스트 결과.
5. README에 실제 배포 주소, 콘텐츠 추가 방법, 재배포 방법, 남은 제한사항 기록.

배포 계정이나 권한이 없으면 실행 가능한 구현과 배포용 빌드까지 완료하고, 필요한 계정 연결을 명시한다. 링크가 실제로 열리는지 확인하기 전에는 배포 완료라고 보고하지 않는다.

## 11. 완료 판정 기준

| 검증 항목 | 통과 기준 |
| --- | --- |
| 진입 | 공개 URL에서 홈이 표시되고 두 게임을 선택할 수 있음 |
| 콘텐츠 | 국내 인물 149문제·해외 인물 108문제·캐릭터 14문제·사물 252문제에 실제 사진과 올바른 정답이 있고 수량·출처가 기록됨 |
| 기본 플레이 | 시작부터 정답 공개, 다음 문제, 결과, 한 판 더까지 진행 가능 |
| 중복 방지 | N개 문제는 한 주기에서 각각 한 번만 출제됨 |
| 주기 경계 | N ≥ 2이면 직전 문제와 다음 주기의 첫 문제가 다름 |
| 라운드 경계 | 한 판 더·홈 이동·새로고침이 출제 기록을 임의로 초기화하지 않음 |
| 라운드 내부 | 주기가 도중에 바뀌어도 같은 라운드에서 같은 사진이 반복되지 않음 |
| 시간 | 이미지 표시 후 5초가 지나면 한 번만 시간 초과 및 정답 공개 |
| 조기 판정 | 정답·패스 후 남아 있던 타이머가 다음 문제에 영향을 주지 않음 |
| 점수 | 정답 인정은 문제당 1점이며 최종 판정 개수의 합이 진행 문제 수와 같음 |
| 일시정지 | 수동 정지·탭 전환 시 남은 시간이 보존되고 복귀 후 수동 재개 |
| 오류 처리 | 잘못된 이미지·빈 목록·저장소 오류가 무한 로딩이나 화면 멈춤을 만들지 않음 |
| 입력 | 터치·키보드로 진행 가능하며 빠른 연속 입력이 문제를 건너뛰지 않음 |
| 화면 | 390×844, 844×390, 1366×768, 1920×1080에서 핵심 UI가 잘리지 않음 |
| 전체화면 | 지원 환경에서는 진입·종료 가능, 미지원 환경에서도 플레이 가능 |
| 배포 | 운영 URL 직접 접속·새로고침 시 화면 및 이미지가 정상 표시됨 |

자동 검증은 출제 대기열과 타이머·판정 경합처럼 오류가 게임 진행에 영향을 주는 로직에 집중한다. 화면 크기·사진 가독성·전체화면·터치 조작은 실제 브라우저에서 확인한다.
